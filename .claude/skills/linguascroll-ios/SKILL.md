# LinguaScroll iOS app

## Stack and rules

- iOS 17 minimum, Swift 6 strict concurrency, SwiftUI. UIKit only where needed (the feed collection view).
- No third-party dependencies except the OpenAPI runtime. Native only (no React Native, no Flutter).
- Swift packages: `APIClient` (generated by swift-openapi-generator from `api/openapi.yaml`, never hand-edited), `Core`, `Features`. Regenerate with `make gen`.
- `@Observable` models, async/await, protocols for every service so tests use fakes.
- String Catalogs for all text; leading/trailing layout.
- Debug builds talk to `http://localhost:8080` (ATS exception for localhost only).
- No paid Apple Developer membership yet: simulator and free provisioning. No push, Sign in with Apple, universal links or TestFlight in v0.

## Identity (no accounts in v0)

- `InstallID.current()`: random UUID in the Keychain, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, not synced. Survives reinstall, not a new phone.
- Session token also in the Keychain. Send `Authorization: Bearer <token>`.
- On 401: re-register via `POST /v1/sessions/anonymous` with the same install ID (server returns the same user), retry once.
- No IDFA, no App Tracking Transparency prompt.
- Age block: on 403 `age_blocked`, store the block in the Keychain and show the blocked screen on every launch.


Tabs: Feed and Me. `GET /v1/config` on launch.

## The YouTube feed (the hard part)

- `FeedViewController`: UIKit collection view, vertical paging, wrapped for SwiftUI.
- Pool of exactly 2 `WKWebView` players (current and next). Memory must stay flat over 50 swipes.
- Each web view is loaded once with the YouTube IFrame API via `loadHTMLString(_:baseURL:)`, baseURL `https://<bundle id lowercased>` (YouTube requires that Referer). `allowsInlineMediaPlayback = true`, `mediaTypesRequiringUserActionForPlayback = []`.
- Player vars: `playsinline=1`, `rel=0`; when `has_captions`, `cc_load_policy=1` and `cc_lang_pref=<clip language>` (unless the user turned captions off in Settings).
- Next clip is cued with `cueVideoById` (loaded, paused, silent) as soon as the current one starts playing.
- Play only when the cell is more than half visible; pause immediately otherwise. Never two audio tracks. Loop by seeking to 0 on `ended`.
- State and position come back through `WKScriptMessageHandler`. Watched time is real playback time.
- Swipe over the player: disable the web view's own scroll view and let the collection view's pan recognise simultaneously so taps still reach YouTube's controls. Prove this on a real device first; fallback is a swipe strip in the bar.
- NEVER add any subview, gesture recogniser action or overlay on top of the player frame. Controls live in the bar below (>= 64 pt).
- Audio session `.playback`; pause on backgrounding.

## Behaviour

- Fetch the next page when 5 clips remain.
- Like/save optimistic with rollback toast; hide/block animate away and advance.
- Player error: log `player_error`, auto-advance after 1 s; codes 101 and 150 also call `PUT /v1/videos/{id}/hide`.
- Share: share sheet with `https://youtube.com/shorts/<id>`.
- Thumbnails from YouTube's public thumbnail URL; never store images.

## Events

`impression` (cell becomes current, `position`), `view_end` (`watched_ms`, `duration_ms`, `loops`, `completed`, `ttff_ms`), `share`, `player_error` (`code`). Batched in memory and on disk, flushed every 10 s and on backgrounding, each with a client UUID so retries don't double count. `ttff_ms` = from becoming current to first `playing` state; target median < 800 ms on Wi-Fi.

## When writing code

1. Name the module (V5 shell/onboarding, V6 feed, V7 Me/settings) and stay inside it.
2. Use the generated `APIClient`; if an endpoint is missing, change `openapi.yaml` and regenerate, don't hand-roll requests.
3. Add unit tests with fakes (Keychain ID, 401 recovery, event retry, pool state machine).
4. Check the overlay rule before finishing any feed change.
